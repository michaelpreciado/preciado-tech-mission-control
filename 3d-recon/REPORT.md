## 3. Performance hotspots and budget implications

1. **Current global costs: rain and continuous navigation rendering.** Rain redraws the full viewport at capped DPR while CoreOrb renders continuously in full motion. Their bottlenecks differ: canvas fill/text/compositing versus a small WebGL scene. Verify real backing-store dimensions and time in each before optimizing triangle count. CoreOrb's coarse-pointer behavior differs from the shared motion helper: mobile does not automatically mean static.
2. **Current graph CPU cost: MemoryGraph.** Synchronous 260-tick layout can block the main thread and runs after fresh polls, including while manually showing list view. Profile largest expected vault; reuse stable layouts or move layout computation off-thread if needed. This is a 2D CPU hotspot, not a WebGL issue.
3. **Latent heavyweight scene: HoloHud3D.** Continuous auto-orbit, animated leaves even when idle, per-node meshes/HTML and unbounded local roster size would add substantial work if reattached. Explicitly bound nodes, batch repeated bodies, gate visibility/motion, and budget shadow updates before asset integration. Damping already exists; absence of damping is not the issue. Confirm geometry disposal during repeated active/idle changes with renderer memory counters.
4. **Latent backdrop: AmbientNeuralField.** 380 points are bounded, not an unbounded particle leak. The setup is quadratic and frame-time drift is CPU-driven; fullscreen additive coverage and another context are likely more important. Fix disconnected link endpoints and refresh-rate-dependent camera interpolation if ever restored. Its comment promising hidden-tab handling is not implemented locally.
5. **Instance scenes already have useful safeguards.** Ring ≤96 + Pipeline ≤68 = ≤164 orbital instances, plus CoreOrb's 192 points. Approximate visible-scene draw-call structure at full occupancy: CoreOrb 3 + Kanban ≤4 + Pipeline 6 = **≤13**, excluding renderer internals and support detection; this is a source estimate, not a capture. No unbounded particle accumulation was found. Preserve scratch-object reuse, clamped delta, exponential scale damping and explicit disposal.
6. **Resource churn and compositing.** Polls reconstruct orbital guides; Canvas key changes remount renderer resources. Tilt's per-event layout reads and permanent layer hints merit checking with many cards. Avoid blanket bloom, many transparent shells, separate canvases for every planet, or high-resolution textures for tiny nav elements.

Existing app routes appear to mount at most one Three.js Canvas through the active CoreOrb placement, plus the Canvas2D rain surface; dormant canvases do not create current contexts. CoreOrb's support probe separately calls getContext on a temporary canvas. Browser visibility handling can pause rAF independently, but this audit distinguishes that behavior from explicit application gates.
