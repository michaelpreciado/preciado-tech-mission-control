## 3. The orb — 3D, matrix blue, 120fps budget
Three.js stack is already installed: `three@0.185.1`, `@react-three/fiber@^9`,
`@react-three/drei@^10`. NO new npm dependencies.

Design a small arc-reactor: glowing plasma sphere (fresnel/rim shader or emissive
material + a couple of point lights), a thin outer ring (torus, slow counter-rotation),
and ~150–250 tiny particle specks orbiting. Palette = existing tokens ONLY:
`--pt-neon` / `rgba(var(--pt-neon-rgb), …)` for blue (see lib/tokens.ts — the blue is
the brand accent there), semantic `error` red (`SEMANTIC` in lib/tokens.ts) for heat.
Red is ALWAYS semantic, never decorative — it may appear ONLY in the heat state.
Preciado Tech creative touch: a faintly etched brand mark in the core center
(Icon name="brand" as a low-opacity sprite/CSS layer OR a subtle hex facet pattern in
the shader — pick the cheaper one). Keep it tasteful; this is matrix CRT, not a carnival.

Performance contract (this is the part that must be bulletproof):
- The canvas is ≤64px square. Total pixels including DPR ≤ ~15k. Keep per-frame work
  trivial so rAF comfortably holds 60 and the compositor can hit 120 on
  ProMotion-class panels (desktop is an RTX 5070 Ti box; assume high refresh).
- Clamp `dpr={[1, 1.5]}` (fiber Canvas prop). No postprocessing passes, no drei helpers
  that spawn extra scene graphs. Single sphere + ring + Points object, nothing heavier.
- `prefers-reduced-motion: reduce` → static orb: render once, no rAF loop, constant
  glow. Respect it.
- `document.visibilityState !== 'visible'` → set `frameloop="demand"` (or pause) so a
  background tab costs ~0. Resume on visible.
- No SSR: dynamic import, and the R3F Canvas lives in `useEffect`-guarded client code.
- Do NOT add `text-shadow` rules to app/globals.css (the budget is frozen). Orb glow is
  box-shadow/canvas luminance only.

## 4. Heartbeat state machine (the fun part)
States, driven by REAL data — never hardcoded loops of fake activity:

| state | trigger | look |
|---|---|---|
| `idle` | no tasks, metrics < 30% | slow 6s breathing, dim glow, gentle 0.05 rad/s rotation |
| `active` | ≥1 kanban task running/claimed OR SSE event bus firehose ( /api/events ) delivered events in the last 20s | faster spin (~0.4 rad/s), brighter core, particles speed up |
| `surge` | any of cpuPct > 70, load1/cores > 0.75, any gpu util > 70 (from /api/telemetry) | pulse rate scales with metric (lerp intensity 0.5→1.0), ring counter-rotation quickens, subtle flicker |
| `hot` | cpuTempC ≥ 80 **or** any GPU temp ≥ 85 | cross-fade glow blue→red (semantic error color) in ~1.5s, heartbeat pulses ~1Hz, holds while temp ≥ threshold, cools back to blue with 3s hysteresis below 75/80 |

Data wiring (do NOT spin up a private fetch loop in the orb — read what exists):
- `useLiveData()` (components/LiveDataProvider.tsx) is global: it already polls
  /api/mission-control (openTasks, enabledCronJobs, warnings) and subscribes to the
  /api/events SSE firehose (debounced ≥6s, visible-tab only, ~line 140-160). Extend the
  provider (or a sibling `OrbBus` context in the same file) to expose a lightweight
  `activity` signal: a timestamp of the last SSE event + running-task count. Keep
  per-event updates cheap (a ref + version counter or a 1Hz heartbeat), not 60Hz
  setState storms.
- Telemetry: poll `/api/telemetry` ONCE PER 5–10s (mirror how components/views/RigHud.tsx
  consumes it — read that fetch first; it returns HostMetrics with `cpuPct`, `cpuTempC`,
  `loadavg`, `gpus[]` incl. per-card `temperature` + `utilization` — see lib/host-metrics.ts,
  HostSample). Store the latest sample in a `useRef` the orb's useFrame reads. Do NOT
  re-render the whole shell per sample. Skip the poll when tab hidden.
- Derive state in one pure function `deriveOrbState(latest: HostSample | null, activity: Activity) -> OrbState`
  in a new `lib/orb-state.ts` with unit tests covering: idle/active/surge/hot, the 80/75
  hysteresis, and null-sample → idle.
